## 2. API 变化

| 接口 | 方法 | 用途与请求 | 成功响应 | 关键错误码 |
|---|---|---|---|---|
| `/api/import/validate` | POST | `{context,fileName,content}`；服务端解析并质检 | `source=local_import_service`，返回 `batchId/status/file/quality/issues/preview`；最多 20 条预览、500 条问题 | `IMPORT_UNSUPPORTED_FILE`、`IMPORT_FILE_TOO_LARGE`、`IMPORT_EMPTY_FILE`、`IMPORT_INVALID_CSV`、`IMPORT_INVALID_JSON`、`IMPORT_SCHEMA_MISMATCH`、`IMPORT_NO_VALID_ROWS` |
| `/api/import/:batchId/confirm` | POST | `{context}`；教师确认仅采用有效记录 | `status=confirmed`、有效/排除数、确认时间及批次摘要 | `IMPORT_BATCH_NOT_FOUND`、`IMPORT_CONTEXT_MISMATCH`、`IMPORT_NO_VALID_ROWS` |
| `/api/analyze` 批次模式 | POST | `{context,batchId}`；从运行时库聚合有效数据并调用原 Skill | `source=local_skill`，Skill 结果及 `_evidence`（批次、文件哈希、行数、学生数、Skill ID/版本、时间） | `IMPORT_BATCH_NOT_FOUND`、`IMPORT_CONTEXT_MISMATCH`、`IMPORT_BATCH_NOT_CONFIRMED`、`ANALYSIS_FAILED` |
| `/api/import/latest?context=...` | GET | 按班级恢复最近批次 | 批次、质量问题、最近研判；无数据时 `data:null` | `INVALID_CONTEXT` |

原 `/api/analyze` 的 `scores + knowledgePoints` 直接输入模式继续可用。批次模式不调用 `fromState()`、`syntheticScores()` 或随机成绩。当前仅用 `teacher:*` context 隔离批次，**不是生产级身份授权**；真实身份权限属于 M4。

## 3. 数据库与安全

- 运行时库默认路径：`data/runtime/zhixue_runtime.sqlite`。测试使用 `:memory:` 或系统临时目录；启动时幂等执行 `db/runtime-schema.sql`，不清空历史数据。
- 新表：`runtime_import_batches`、`runtime_import_records`、`runtime_quality_issues`、`runtime_analysis_runs`。批次、规范化记录和质检问题在一个事务内写入。
- 不落盘原始 CSV/JSON；只记录文件名、格式、大小、SHA-256、规范化记录和质检结果。额外列不持久化。手机号、邮箱、证件号命中的匿名编号被阻断并不写入原文。
- 基线 `data/zhixue_demo.sqlite` **未发生变化**。原 ZIP 条目与当前工作副本 SHA-256 均为 `BBA0FC13A8332286BE5ACEF3E190FCB3ABF54F92648254C100073E83873922C4`。
- `/data/runtime/zhixue_runtime.sqlite` 不在静态文件白名单；HTTP 测试返回 404。运行时库被 `.gitignore` 排除。
