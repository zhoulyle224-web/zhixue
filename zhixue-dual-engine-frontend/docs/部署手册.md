# 部署手册

## 1. 环境要求

| 方式 | 最低要求 | 推荐 |
|---|---|---|
| Node 本地运行 | Node.js 22.13+ | Node.js 24 LTS |
| Docker | Docker Engine 24+、Compose v2 | 4 核 CPU、8 GB 内存 |
| 浏览器 | Chrome/Edge 最新版 | 1366x768 以上 |
| 磁盘 | 500 MB | 2 GB，用于日志和备份 |

本地 MVP 不要求 `npm install`，不要求 GPU，不访问外网。

## 2. Windows 部署

一键部署并打开：

```text
双击“deploy-and-open.bat”或“一键部署并打开.bat”
```

该脚本会自动检测 8080 至 8090 端口，后台启动本地服务，并打开默认浏览器。

命令行部署：

```powershell
cd zhixue-dual-engine-frontend
.\scripts\start-zhixue.ps1
```

指定端口：

```powershell
.\scripts\start-zhixue.ps1 -Port 8081
```

健康检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8080/api/health
```

## 3. Linux 部署

```bash
cd zhixue-dual-engine-frontend
chmod +x scripts/start-zhixue.sh
./scripts/start-zhixue.sh
```

后台运行示例：

```bash
nohup sh scripts/start-zhixue.sh > zhixue.log 2>&1 &
```

## 4. Docker Compose 部署

```bash
docker compose up -d --build
docker compose ps
curl http://127.0.0.1:8080/api/health
```

停止：

```bash
docker compose down
```

查看日志：

```bash
docker compose logs -f zhixue
```

## 5. 内网离线部署

1. 在联网环境准备 Docker 镜像或 Node 运行包。
2. 将整个项目、镜像和匿名数据库拷贝到内网。
3. 通过 SHA-256 校验项目包和数据文件。
4. 启动服务，不执行任何联网安装。
5. 检查 `/api/health` 中 `services.network` 是否为 `not_required`。

离线模型需要提前把 Ollama 模型文件放入内网机器：

```bash
ollama serve
ollama create zhixue-qwen -f Modelfile
```

## 7. 备份与恢复

备份：

```powershell
.\scripts\backup-local.ps1
```

恢复前先停止服务，再覆盖数据库：

```powershell
Copy-Item .\backups\zhixue_demo-时间戳.sqlite .\data\zhixue_demo.sqlite -Force
```

Docker 审计卷备份：

```bash
docker run --rm -v zhixue-runtime:/data -v "$PWD/backups:/backup" alpine \
  tar -czf /backup/runtime-audit.tar.gz -C /data .
```

## 8. 常见错误

| 错误 | 排查 |
|---|---|
| `EADDRINUSE` | 更换端口或释放 8080 |
| `node:sqlite` 不存在 | Node 版本低于 22.13，升级 Node |
| 数据库文件不可读 | 检查文件权限和路径 |
| 页面 CSS/JS 404 | 确认从服务根路径访问，不要直接打开本地 HTML |
| 导出 403 | 检查 `role` 与 `context` 是否属于同一角色 |
| 审计卷只读 | 检查 Docker 卷和目录权限 |
| 断网后模型失败 | 属于预期降级，使用本地 Skill 继续演示 |
