# 架构与目录治理

## 当前分层

- `assets/`：浏览器端界面、状态管理和本地 Skill。
- `server/`：本地 Node API、鉴权、学习服务、模型适配和 SQLite 持久化。
- `worker/`：线上展示环境的服务入口。
- `scripts/`：构建、验收、发布和工作区维护工具。
- `data/`：合成演示基线；`data/runtime/` 为本机运行数据。

## 构建治理

公开页面清单集中在 `scripts/lib/project-layout.mjs`，静态构建与托管构建共同调用
`scripts/lib/build-client.mjs`，避免两条构建链路逐渐产生页面遗漏或资源差异。

所有递归删除必须经过 `scripts/lib/fs-safety.mjs` 的目录边界检查。构建脚本只允许重建
项目根目录下的明确子目录，不能删除项目根目录或越出项目范围。

构建和清理命令共用项目锁。如果误操作为并行构建或边构建边清理，后启动的任务会明确
提示等待，避免两个进程同时改动 `dist/` 导致产物损坏；异常退出留下的失效锁会自动恢复。

## 清理规则

运行 `npm run clean` 只删除以下可再生成内容：

- `dist/`：构建输出；
- `release/`：发布暂存目录；
- `.tmp/`：临时缓存。

以下内容必须保留，不能视作垃圾文件：

- `data/runtime/`：SQLite、审计日志和演示沙箱；
- `backups/`：用户备份；
- `outputs/`：已经交付的压缩包等产物。

需要清除运行数据时，应先备份并由操作者明确选择，不能复用普通清理命令。
