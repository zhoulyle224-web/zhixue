# 智学双擎 Skill 重构与新增清单

> 状态：已确认并完成第一版实现  
> 版本：V1.0  
> 日期：2026-09-20

## 1. 知识库总体范围

知识库不再只保存少量预设问答，而是分成四层：

### K0 通用基础知识

- 基础算术，例如 `1+1=2`、百分数、比例、单位换算。
- 基础逻辑、集合、函数、方程和常见科学常识。
- 常用中文学习表达、术语解释和学习方法。
- 简单计算优先调用确定性计算工具，不依赖模型猜答案。

### K1 计算机大类公共基础知识

参照中国普通高校计算机类专业常见课程体系，至少覆盖：

- 高等数学、线性代数、概率统计、离散数学。
- 程序设计基础，主要包含 C/C++、Java、Python 的通用概念。
- 数据结构与算法。
- 计算机组成原理、数字逻辑。
- 操作系统。
- 计算机网络。
- 数据库系统。
- 软件工程。
- Web 开发基础。
- 人工智能导论、机器学习基础。
- 信息安全、数据安全和人工智能伦理基础。

### K2 具体课程知识

- 当前学校、当前课程的教学大纲、章节、课件、实验指导、习题和教师补充材料。
- 每条知识应保存课程、章节、知识点、难度、先修关系、版本和来源。
- 回答具体课程问题时优先使用 K2，并给出可以定位的引用。

### K3 学生个人学习上下文

- 当前课程掌握度、错题、任务、出勤、答疑和学习计划。
- K3 只用于调整解释难度、例子、学习路径和任务建议，不作为公共知识事实来源。
- 必须按学生本人或当前任课教师授权范围读取，不得跨学生、跨课程混用。

## 2. 知识检索与回答原则

回答时按照以下顺序工作：

1. 判断问题所属课程、知识领域和难度。
2. 简单算术或确定性计算使用计算工具直接求解。
3. 优先检索当前课程 K2。
4. K2 不足时检索计算机公共基础 K1。
5. 普通基础问题检索 K0。
6. 使用 K3 调整讲解方式，但不能泄露其他学生信息。
7. 明确标注答案来源为“当前课程资料”“计算机公共基础”或“通用基础知识”。
8. 没有可靠依据时先澄清或建议转教师，不得伪造引用。

## 3. 建议保留并重构的现有 Skill

### S01 `course-ai-tutor`：课程智能助教

**处理方式：重做。**

作用：理解学生的自然语言问题，在 K0～K3 中检索相关知识，生成分步骤、符合学生当前水平的回答，并支持连续追问。

主要能力：

- 回答基础知识和计算机专业问题，不再要求问题必须包含预设关键词。
- 支持同义表达、错别字、概念比较、计算题、代码解释和“为什么”等追问。
- 课程资料回答附课程引用；公共知识回答明确标注知识层级。
- 根据学生掌握度选择基础解释、类比解释、例题或进阶解释。
- 资料不足时先澄清，再由学生选择是否转教师。

### S02 `academic-performance-analyzer`：班级学情分析

**处理方式：重做。**

作用：直接读取数据库中的班级、成绩、题目、知识点、出勤、任务和答疑数据，生成班级整体学情分析。

主要能力：

- 不再把外部 CSV/JSON 导入作为日常使用前提。
- 计算班级平均成绩、及格率、知识点掌握度、趋势和风险分布。
- 识别共性问题、分层差异和需要教师关注的学生。
- 每个结论提供数据来源、样本量、时间范围和证据。

### S03 `classroom-interaction-generator`：课堂互动设计

**处理方式：升级。**

作用：根据当前班级薄弱知识点和课程进度，生成课堂问题、讨论活动、练习和教学游戏。

主要能力：

- 输入不再只是知识点名称，还包含班级掌握度和常见错误。
- 为基础、提升和拓展学生设计不同参与方式。
- 输出活动目标、流程、时间、题目、答案、观察指标和课后反馈方式。

### S04 `course-content-optimizer`：课程内容优化

**处理方式：升级。**

作用：根据班级学情、学生答疑、任务反馈和教学效果，对课程章节、案例、资源和考核方式提出调整建议。

主要能力：

- 指明需要补讲、重排、删减或增加的内容。
- 推荐与中国普通高校计算机课程相匹配的案例类型和实践任务。
- 说明建议依据、影响范围和预期效果。
- 只生成修改建议，由教师确认后实施。

### S05 `teacher-answer-manager`：教师答疑管理

**处理方式：升级。**

作用：聚合学生问题和智能助教未解决的问题，帮助教师批量处理高频问题和个别问题。

主要能力：

- 按课程、班级、知识点、问题类型和解决状态聚类。
- 识别高频误解、代表性问题和需要单独辅导的学生。
- 生成教师回复草案、班级 FAQ 和后续教学建议。
- 教师确认后才向学生发送回复。

## 4. 建议新增的核心 Skill

### S06 `knowledge-base-curator`：知识库构建与治理

**处理方式：新增。**

作用：负责把 K0、K1、K2 知识整理成可检索、可引用、可更新的统一知识库。

主要能力：

- 按学科、课程、章节、知识点和先修关系建立知识目录。
- 对课程资料进行切片、去重、标签化、版本管理和质量检查。
- 识别冲突、过期、缺少来源或无法引用的知识。
- 为检索生成关键词索引和语义索引。
- 知识更新不直接覆盖旧版本，保留来源和变更记录。

### S07 `student-profile-analyzer`：学生学习画像分析

**处理方式：新增。**

作用：综合当前学生在当前课程中的成绩、知识点、错题、任务、出勤、答疑和学习行为，形成可解释的个人学习画像。

主要能力：

- 输出优势知识点、薄弱知识点、先修缺口、学习趋势和任务执行情况。
- 区分“不会”“粗心”“先修不足”“练习不足”“任务拖延”等不同原因。
- 每个判断附数据证据和置信度。
- 只分析学习相关表现，不推断性格、心理疾病、家庭情况等敏感特征。
- 教师只能查看当前教学关系范围内的学习数据，其他学生无法观测。

### S08 `personalized-learning-planner`：个性化学习方案制定

**处理方式：新增。**

作用：根据学生画像、课程目标和可用资源，为单个学生自动生成生效的差异化学习方案。

主要能力：

- 制定本轮目标、知识点顺序、任务、资源、难度、预计时长和截止时间。
- 根据学生基础选择补偿学习、标准提升或拓展挑战路线。
- 说明“为什么推荐”，并关联具体画像证据。
- 避免只给同一分层学生复制完全相同的任务。
- 方案自动生效，任课教师可以查看并按教学判断调整。

### S09 `exercise-coach`：练习生成与错因诊断

**处理方式：新增。**

作用：围绕学生当前薄弱知识点生成适量练习，检查答案并诊断错误原因。

主要能力：

- 生成概念题、计算题、代码题、案例题和逐步提示。
- 根据学生答题情况动态调整难度。
- 区分知识错误、步骤错误、代码语法错误、边界遗漏和粗心错误。
- 不直接泄露完整答案；先提供分级提示，再给解析。
- 结果写回错题和掌握度证据，供画像和下一轮计划使用。

### S10 `learning-effect-evaluator`：学习效果评估与计划调整

**处理方式：新增。**

作用：比较计划执行前后的数据，判断个性化方案是否有效，并生成下一轮调整建议。

主要能力：

- 对比知识点掌握度、错题、任务、答疑和完成时间的变化。
- 判断目标是否达成、哪些任务有效、哪些任务需要替换。
- 识别逾期、反复错误和短期成绩上升但掌握不稳定等情况。
- 给出保持、加练、降难度、换解释方式或教师介入建议。
- 保留每轮计划版本和评估依据。

## 5. Skill 之间的协作关系

```text
knowledge-base-curator
  ├─ 为 course-ai-tutor 提供 K0/K1/K2 检索知识
  ├─ 为 classroom-interaction-generator 提供课程知识
  ├─ 为 course-content-optimizer 提供课程结构
  └─ 为 exercise-coach 提供知识点和题目依据

academic-performance-analyzer
  └─ 输出班级层面的整体问题与学生范围

student-profile-analyzer
  ├─ 读取学生个人学习证据
  └─ 输出给 personalized-learning-planner

personalized-learning-planner
  ├─ 调用 exercise-coach 生成针对性练习
  └─ 自动向本人学习空间生效，教师可查看和调整

course-ai-tutor + exercise-coach + 学生任务反馈
  └─ 产生新的学习证据

learning-effect-evaluator
  ├─ 评估本轮计划
  └─ 反馈给 student-profile-analyzer 和下一轮计划

teacher-answer-manager
  └─ 把个别答疑问题反馈给班级教学和课程优化
```

## 6. 推荐优先级

### 第一批：必须先完成

1. `knowledge-base-curator`
2. `course-ai-tutor`
3. `student-profile-analyzer`
4. `personalized-learning-planner`

这四个 Skill 决定“能否真正回答问题”和“能否体现学生个性化”。

### 第二批：形成学习闭环

5. `exercise-coach`
6. `learning-effect-evaluator`
7. `academic-performance-analyzer`

### 第三批：加强教师端

8. `teacher-answer-manager`
9. `classroom-interaction-generator`
10. `course-content-optimizer`

## 7. 所有 Skill 的统一要求

- 输入和输出使用明确 JSON Schema。
- 输出包含 `skill_id`、`skill_version`、生成时间、数据范围和证据。
- 不得把前端写死内容包装成实时分析结果。
- 失败时返回原因、是否保存、是否可重试和建议操作。
- 所有学生数据必须经过服务端权限检查。
- 教师发布内容必须经过教师确认。
- 公共知识和课程知识必须区分来源。
- 无真实模型时必须显示降级模式，不能声称已经进行大模型推理。
- 知识资料必须使用可授权、可引用或自行编写的内容，不直接复制受版权保护教材全文。

## 8. 已确认内容

以下方案已确认并纳入实现：

1. 是否采用上述 K0～K3 四层知识库。
2. 是否保留并升级现有 5 个 Skill。
3. 是否新增 S06～S10 共 5 个 Skill。
4. 是否按“第一批 → 第二批 → 第三批”顺序实施。
5. 智能问答是否采用“真实模型 Provider＋无模型时明确降级”的双模式。
6. 个性化方案是否坚持“Skill 按当前学生数据自动生成、教师可查看和调整”。
