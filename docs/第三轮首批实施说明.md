# 第三轮首批实施说明

本提交是已确认需求的首批 P0 落地，不声称一次性完成 FR-01～FR-12 的全部产品范围。

## 已落地

- 基于独立 Git 工作树实施，未把原工作目录的未提交源码、运行数据库或输出文件带入确认版本。
- 运行数据按 `demo / test / production` 环境目录隔离；发布与 Git 忽略所有运行数据库、密钥目录和日志。
- 导入批次形成 Raw 元数据、Staging 脱敏记录、Quarantine 异常记录；确认后事务性生成 Curated 数据版本与 Serving 快照。
- Curated 记录使用内容指纹幂等；隔离记录不进入可信版本。激活新版本时上一版本转为 inactive，失败事务回滚。
- 增加统一 `ModelGateway`，内置通义千问、DeepSeek、硅基流动和 OpenAI 四个服务端安全预设；业务层不读取 API Key，也不直接调用供应商 SDK。
- 教师演示管理员账号增加 `manageAi` 能力。前端“AI 接口”可选择 Provider、填写模型名称并为每家独立录入 API Key；服务端验证成功后把密钥写到隔离存储，数据库仅保存 `secret_ref` 和后四位。
- 增加 `/api/v1/admin/ai/status`、`/api/v1/admin/ai/key`、`/api/v1/ai/qa/sessions`、`/api/v1/ai/qa/sessions/:id/messages`、`/api/v1/ai/runs/:runId` 和 `/api/v1/admin/data/status`。
- 新版课程问答由 `course-ai-tutor` 检索后经 `ModelGateway` 生成；无模型时明确返回“AI 未生成”，模型伪造或缺失引用时降级为课程检索结果。
- AI 运行保存 `requestId`、用途、Skill/模型版本、证据、状态、耗时与 Token；只有业务记录落库后才进入 `completed_persisted`。

## 后续批次

- P1：课程/资源版本、作业与公告的完整服务端闭环。
- P2：将学生画像、个人计划和效果评估全部切换为各自 Skill + ModelGateway，并完成处方效果卡与下一轮调整。
- P3：轻量课堂互动和外部 LMS 增量同步。

所有后续批次继续以自动化测试证明真实生成、持久化、权限和数据隔离，不使用前端静态成功状态代替业务完成。
