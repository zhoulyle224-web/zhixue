# 架构说明

## 运行面

项目保留两个边界清晰的运行面：

1. **本地正式版**：`server/local-api.mjs` 组合身份、授权、答疑、导入研判、任务和导出服务，使用只读 baseline SQLite 与独立 runtime SQLite。
2. **公开展示版**：根目录静态页面和 `worker/index.js` 只提供受限展示；身份、写入和正式导出接口默认失败关闭。

本地正式版是唯一完整能力入口。公开版不复制正式数据和业务写模型。

## 服务端边界

```text
local-api.mjs（组合根 / 路由分发）
├─ http-utils.mjs（JSON、文本响应与请求体上限）
├─ static-service.mjs（静态白名单、路径校验与安全响应头）
├─ auth-service.mjs + authorization.mjs（身份与对象级授权）
├─ qa-service.mjs + course-knowledge.mjs（课程证据答疑）
├─ import-service.mjs + runtime-store.mjs（质检、研判与持久化）
├─ task-service.mjs（任务版本、发布、完成与反馈）
└─ export-service.mjs（白名单导出、脱敏、水印与严格审计）
```

`local-api.mjs` 只负责依赖装配和请求分发；通用 HTTP 处理与静态文件安全边界不再与业务路由混杂。

## 构建边界

- `npm run build`：用内置 Node.js 文件 API 生成 `dist/client`、`dist/server` 和 `dist/.openai`。
- `npm run build:static`：只生成可部署的静态页面与资源。
- `npm start`：启动本地正式版，不依赖构建产物。

项目不需要 React、Vinext、Vite、Drizzle ORM 或安装 `node_modules`。D1 的公开只读结构继续由 `drizzle/` 中的 SQL 迁移描述，避免为执行 SQL 引入 ORM 工具链。

## 数据边界

- `data/zhixue_demo.sqlite`：只读、匿名合成 baseline。
- `data/runtime/<environment>/`：按 demo/test/production 隔离的 Session、五区数据版本、AI 运行、审计与业务写入；被 Git 和发布脚本排除。
- `server/model-gateway.mjs`：唯一模型出口，校验服务端预设地址允许列表并统一超时、错误分类和响应元数据。
- `server/secret-store.mjs`：保存 API Key 的独立受保护目录；SQLite 只记录 `secret_ref` 和后四位。
- `data/web_snapshots.json`：服务端读取的合成快照。
- `assets/demo-data.json`：只允许公开展示的数据。

静态服务使用页面和 `assets/` 双白名单，不会暴露 `data/`、`server/`、`tests/` 或仓库中的其他文件。
