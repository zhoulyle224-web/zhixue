# 智学双擎第二轮功能升级需求说明

> 文档状态：已确认并执行（实现以代码与自动化测试为准）  
> 版本：V1.1
> 日期：2026-09-20  
> 依据：用户提出的 5 项修改要求、教师端数据导入页面截图、学生端答疑页面截图，以及当前项目代码与数据库结构核查结果。

> 2026-09-20 补充确认：以下最新决定覆盖本文中较早的“学生可选共享”和“教师确认发布个人计划”条款：班级学生页只显示概览，选择学生后进入独立详情页；学习相关数据按教学关系自动对任课教师开放；学生端不提供共享权限选择；个人方案按学生当前数据自动生成并生效，教师可以查看和更改；报告与复盘改为页面直接展示，不再要求导出。

## 1. 本轮目标

本轮升级要把当前“两个相互独立的演示账号页面”改造成一条真实、连续、可追踪的教学链路：

```text
教师登录
  → 直接读取本人所授课程、班级和学生数据
  → 选择一名学生进入“教师观察视角”
  → 进入独立详情页查看该学生的课程学习数据与智能分析
  → 查看或调整系统自动生效的个性化学习计划
  → 学生在本人空间执行计划、智能问答并提交反馈
  → 教师查看效果并继续调整
```

同时保留原有学生账号直接登录入口：

```text
学生使用本人账号直接登录
  → 进入完整学生学习空间
  → 查看本人课程、画像和计划
  → 智能问答、完成任务、提交反馈
```

“学生直接登录”和“教师观察学生视角”是两个并行入口：前者是学生本人身份并拥有本人写权限，后者始终是教师身份下的只读观察模式，二者不得合并或相互替代。

本轮不把页面做成“看起来成功”的静态演示。身份切换、数据读取、问答记录、计划发布、任务完成和反馈必须经过服务端鉴权并持久化。

## 2. 已确认的现状问题

| 编号 | 当前情况 | 造成的问题 |
|---|---|---|
| P1 | 教师点击“切换学生视角”时会退出教师 Session，并跳回学生登录页 | 每次往返都要重新登录，演示链路被打断 |
| P2 | 教师“数据导入与质检”仍要求上传 CSV/JSON 后再分析 | 系统已有 SQLite 班级、学生、成绩、掌握度、出勤、错题等数据，却没有直接作为教师主数据源 |
| P3 | 学生数据接口只支持学生本人访问，没有“任课教师查看指定学生公开数据”的授权模型 | 教师无法从班级下钻到单个学生，也无法基于个人证据制定计划 |
| P4 | `course-ai-tutor` 仅按问题中是否包含预设标签或标题来匹配课程片段 | 非预设表达、同义表达、计算题、追问和跨片段综合问题容易被误判为“资料不足” |
| P5 | 当前个性化主要体现为分组标签和统一的分层任务 | 学生之间的目标、学习路径、资源、任务、难度和反馈调整差异不够明显 |

## 3. 产品角色与视角定义

### 3.1 教师身份

- 教师只登录一次，Session 在有效期内保持教师身份。
- 教师可以访问本人所授课程、关联班级及班级内修读该课程的学生。
- 教师不能访问非本人授课课程、非关联班级或未修读当前课程的学生。
- 教师可以查看和编辑系统自动生成的个人学习方案，所有调整记录操作者、对象、时间和版本。

### 3.2 学生身份

- 保留首页和登录页现有的“学生端”入口，学生继续使用本人账号直接登录，不经过教师端。
- 学生直接登录后进入完整学生学习空间，不显示“教师观察视角”横幅。
- 学生登录后只访问本人数据。
- 学生不能通过修改 URL、请求参数或浏览器缓存访问其他学生数据。
- 学生可以查看计划依据、执行任务、提问、追问和提交反馈。
- 当前课程学习数据按真实教学关系自动向任课教师开放，学生不需要配置共享权限。
- 学生直接登录拥有的本人写权限保持有效，包括提问、追问、完成任务和提交反馈。

### 3.3 教师观察视角

“切换学生视角”不再表示退出教师账号并冒充学生登录，而是教师身份下的只读观察模式。

- 入口名称改为“查看学生视角”。
- 点击后先选择当前课程、班级和学生，再进入观察页面。
- 页面顶部固定显示“教师观察视角”“当前学生”“当前课程”和“返回教师工作台”。
- 返回教师端不需要重新登录，并恢复进入观察视角前的页面、课程、班级和滚动位置。
- 观察页面展示当前课程教学所需的学生学习数据，不展示与学习无关的敏感信息。
- 观察模式不得调用学生专属写接口，不得代替学生完成任务、提问或提交反馈。
- 个性化方案按学生当前数据自动生成并生效；教师可在详情页查看和调整，调整操作记录审计。
- 教师观察视角不得占用、注销或修改学生本人直接登录的 Session；学生仍可在另一浏览器或设备正常登录自己的学生端。

## 4. 功能需求

### FR-01 无感进入和退出教师观察视角

#### 用户流程

1. 教师登录后选择课程和班级。
2. 点击“查看学生视角”。
3. 在学生选择器中按姓名、匿名编号、风险等级、任务状态或知识点筛选学生。
4. 选择学生后进入其公开学习视图。
5. 点击“返回教师工作台”直接回到原页面，不触发注销。

#### 服务端要求

- 保留教师 Session，不创建或切换为学生 Session。
- 新增教师观察接口，接口必须同时验证：任课教师、课程教学班、班级、学生选课关系。
- 观察令牌如需存在，只能是短期、只读、绑定教师 Session 与学生范围的服务端令牌，不能写入可伪造的 localStorage 身份字段。
- 每次查看学生详情都写入审计记录，但审计中不保存密码、Session 原文或不必要的敏感正文。

#### 验收标准

- 教师连续往返教师端与观察视角 10 次，无需重新输入账号密码。
- 返回后保持原课程、班级和页面。
- 教师无法在观察视角完成学生任务或替学生发问。
- 修改学生编号、课程编号或班级编号访问越权对象时返回 403。

### FR-02 教师直接读取班级和学生数据

#### 页面改造

- 将主导航“数据导入与质检”改为“班级与学生数据”。
- 教师进入页面后直接加载数据库中的当前教学班快照，不再要求先上传文件。
- 页面分为三层：班级概览、学生列表、学生详情。

#### 班级概览

- 学生总数、平均成绩、及格率、出勤率、任务完成率、待关注人数。
- 知识点掌握度、趋势、风险分布、任务分布和近期答疑主题。
- 显示数据更新时间、数据来源和统计口径。

#### 学生列表

- 每行展示：学生显示名或匿名编号、成绩、掌握度、出勤率、任务完成情况、主要薄弱点、风险状态、最近活跃时间。
- 支持搜索、排序和筛选。
- 点击学生进入详情或教师观察视角。

#### 学生详情

- 当前课程成绩及构成。
- 知识点掌握度与趋势。
- 作业/测验提交情况。
- 错题知识点与复习状态。
- 出勤和课堂参与。
- 已发布计划、任务进度、逾期状态与学生反馈。
- 答疑主题与具体问答正文按当前教学关系展示，并保留读取审计。
- 风险提示必须带证据，不允许只给标签。

#### 数据来源

优先直接读取现有 SQLite 中的课程、教学班、学生、选课、作业、题目得分、出勤、课堂互动、学习事件、掌握度快照、错题、任务和答疑数据。外部文件导入不再作为教师使用主路径。

#### 外部导入处理建议

- 推荐方案：主界面隐藏上传功能，只在“数据管理/高级工具”保留管理员补录入口。
- 补录成功后写入标准业务表，再由同一套查询和分析逻辑读取。
- 不允许上传文件生成一套与系统数据库互不一致的平行结果。

#### 验收标准

- 不上传任何文件即可完成班级概览、学生筛选、个人详情和学情研判。
- 切换课程、班级或学生后，所有数字同步更新且来源一致。
- 数据加载失败时清空旧结果，显示失败原因、是否保存以及重试入口。

### FR-03 学习数据自动开放与隐私边界

#### 共享原则

数据访问遵循“当前课程、当前任课教师、最小必要范围”。教师查看学生数据不等同于其他学生可以查看。

#### 默认向当前任课教师开放

- 当前课程成绩、知识点掌握度和趋势。
- 当前课程作业、任务完成进度和逾期状态。
- 当前课程错题知识点与复习状态。
- 当前课程出勤、课堂参与及风险证据。
- 学生主动提交给教师的任务反馈和求助内容。

#### 按教学关系自动开放的学习明细

- 学习时长和学习设备等行为明细。
- 错题原始作答文本。
- 已被智能助教解决的完整问答正文。
- 自我评价、学习偏好和个人目标。

#### 永不向其他学生开放

- 任何学生的个人画像、成绩、错题、问答、任务、风险和学习行为数据。
- 手机号、邮箱、证件信息、密码、Session、CSRF、内部数据库主键等敏感字段。

#### 产品表现

- 学生端不提供共享权限选择，避免把正常教学流程变成额外配置负担。
- 教师只有在当前课程、当前班级的真实教学关系内才能读取上述学习数据。
- 每次教师读取学生详情都记录教师、学生、课程、班级、字段策略和时间。
- 自动开放不包含手机号、邮箱、密码、Session、证件信息或与学习无关的个人信息。

#### 验收标准

- 教师只能查看本人教学关系内学生的数据。
- 学生 A、学生 B 相互不可见。
- 学生端不存在共享开关，学习数据自动按教学关系开放。
- 所有学生详情读取均有审计记录。

### FR-04 重做智能问答 Skill

#### 目标

把现有“关键词命中预设片段”升级为具备问题理解、多轮上下文、检索、生成、引用校验和不确定性处理的课程智能助教。

#### 问答处理链路

```text
问题输入
  → 安全与隐私检查
  → 意图识别、纠错和指代消解
  → 读取当前课程与当前学生上下文
  → 关键词检索 + 语义检索
  → 片段重排与证据筛选
  → 模型生成答案
  → 引用与课程范围校验
  → 保存对话上下文、反馈和审计
```

#### 回答策略

- 课程资料能够支撑：给出结构化答案和可定位引用。
- 同义表达或非预设问法：仍应通过语义检索命中相关内容。
- 一般基础问题，例如简单计算或通用概念：可以回答，但必须标识“通用知识”，不得伪造课程资料引用。
- 问题含糊：先提出澄清问题，不直接转教师。
- 课程问题确实缺少证据：说明缺少什么，并提供“转教师”选项；只有转交成功后才能显示已转教师。
- 与课程无关、违法或高风险内容：明确说明边界并给出安全建议。

#### 多轮对话

- 支持对上一条回答继续追问，例如“为什么”“再举一个例子”“换一种方法解释”。
- 上下文按学生、课程和会话隔离，切换课程后不得带入其他课程证据。
- 页面显示本轮使用的课程、会话范围和引用来源。
- 学生可以新建对话、查看历史、对答案标记“有帮助/没解决”。

#### Skill 输出契约

至少包含：

- `answer_status`：已解答、需澄清、建议转教师、已转教师、拒绝回答。
- `answer_content`：最终回答。
- `answer_source_type`：课程资料、通用知识、教师回复。
- `evidence`：资源、章节、片段、版本和相关度。
- `confidence`：置信区间或等级。
- `follow_up_questions`：建议追问。
- `session_id`、`turn_id`、`skill_version`、`model_provider`。
- `personalization_basis`：使用了哪些不敏感的个人学习上下文。

#### 模型与部署边界

现有纯 JavaScript 规则匹配不能达到本需求中的开放式智能问答。实现时需要接入真实推理模型，推荐采用可替换的服务端 Provider 接口：

- 在线模式：接入国内可访问的模型服务；密钥只保存在服务端环境变量中。
- 离线模式：没有模型配置时提供课程检索与证据展示，并明确标记“离线检索模式”，不得伪装成生成式智能问答。
- Provider 故障时保留学生问题，不丢数据，并允许重试或转教师。

具体模型供应商和费用策略需要在执行前确认，不能把密钥写进前端或发布 ZIP。

#### 验收标准

- 使用不少于 50 条非预设测试问题，覆盖同义改写、错别字、计算、概念解释、步骤题、追问、无资料和越界问题。
- 课程内问题的关键知识点命中率和引用正确率达到约定阈值；引用必须真实存在于当前课程。
- `1+1=?` 等基础问题不再错误显示为课程资料不足。
- 连续 3 轮追问能正确理解上文，不混入其他学生或其他课程记录。
- 没有模型配置时明确降级，不声称“智能生成成功”。

### FR-05 体现真正的学生个性化教学

#### 学生端新增“今日学习计划”

- 显示当前最需要提升的知识点、目标、原因、预计时间和完成期限。
- 任务按学生个人数据生成，不只按“拓展/提升/巩固”三类复制统一文案。
- 每项任务关联具体资源、练习或问答入口。
- 显示难度、优先级、截止时间、逾期状态和完成证据。

#### 教师端新增“个人计划工作台”

- 从班级学生列表或观察视角进入。
- 系统根据学生当前成绩、知识点、错题、任务、出勤和反馈自动生成有效方案。
- 教师可以编辑目标、任务、资源、难度、预计时长和截止时间。
- 方案生成后直接在学生端生效，不需要教师执行发布动作；教师保存调整后立即生效。
- 支持单人计划，也支持选择多个学生后按各自数据生成不同内容。

#### 自适应闭环

```text
个人数据快照
  → 自动生成并生效
  → 教师查看或调整
  → 学生学习、答疑和完成任务
  → 记录结果与反馈
  → 更新掌握度和风险
  → 给出下一轮计划调整建议
```

#### 个性化依据展示

每份计划必须显示“为什么推荐”，至少列出：

- 主要薄弱知识点和最近趋势。
- 相关错题或作业证据数量。
- 任务完成、逾期和答疑情况。
- 与上次计划相比发生的变化。

#### 验收标准

- 选择 3 名学情不同的学生，生成的目标、任务、难度或资源至少有两项明显差异。
- 教师保存调整后的内容刷新后仍存在，并同步到学生端。
- 学生只能看到自己的计划。
- 完成或逾期状态来自服务端时间和记录，不由前端写死。
- 新反馈能进入下一轮建议，旧计划保留版本和依据。

1. 工作台首页
2. 课程与班级

4. 学情智能研判

1. 学习首页
2. 我的课程

5. 课程智能答疑
6. 学习记录与反馈

### 5.3 教师观察视角

观察视角复用学生页面的信息结构，但必须：

- 显示观察模式横幅。
- 隐藏或禁用学生写操作。
- 展示学习相关详细数据、智能分析与自动个性化方案。
- 提供“保存方案调整”和“返回班级学生概览”。

## 6. 数据与接口需求草案

### 6.1 建议新增或调整的数据

- 系统自动开放策略与教师查看审计记录。
- 教师查看学生数据的审计记录。
- 智能问答会话、轮次、模型信息、检索证据和学生反馈。
- 个人学习计划、计划版本、计划任务、生成依据和发布状态。

### 6.2 建议新增接口

| 方法 | 接口草案 | 用途 |
|---|---|---|
| GET | `/api/teacher/classes/:classId/students` | 获取教师授权班级学生列表 |
| GET | `/api/teacher/students/:studentId/overview` | 获取指定学生可共享概览 |
| GET | `/api/teacher/students/:studentId/observation` | 获取教师观察视角数据 |
| GET/PUT | `/api/student/sharing-preferences` | 兼容旧调用；GET 返回自动策略，PUT 拒绝手动修改 |
| POST | `/api/qa/sessions` | 新建智能问答会话 |
| POST | `/api/qa/sessions/:sessionId/messages` | 发送问题或追问 |
| POST | `/api/qa/messages/:messageId/feedback` | 评价回答效果 |
| POST | `/api/teacher/students/:studentId/plans/drafts` | 兼容入口；获取或生成自动生效方案 |
| PUT | `/api/plans/:planId` | 教师调整当前有效方案 |
| POST | `/api/plans/:planId/publish` | 兼容旧调用；当前有效方案保持生效 |
| GET | `/api/student/plans/active` | 学生读取本人有效计划 |

接口名称可在实现阶段调整，但权限和数据边界不得弱化。

## 7. 非功能要求

### 7.1 安全与隐私

- 所有教师查看学生数据的接口必须在服务端鉴权，不能只靠前端隐藏。
- 教师观察视角只读，禁止身份冒充。
- 模型输入遵循最小必要原则，发送前脱敏；服务端记录 Provider、用途和数据范围。
- 模型密钥不得进入浏览器、日志、Git 或发布包。

### 7.2 数据可信

- 页面数字只能来自当前授权范围和当前数据版本。
- 所有分析、问答和计划都保留数据来源、版本和生成时间。
- 失败时显示发生了什么、数据是否保存以及如何重试。

### 7.3 性能

- 班级学生列表首屏目标 2 秒内可用。
- 学生详情目标 2 秒内加载完成。
- 智能问答在模型正常时应显示处理状态；超时后允许重试，不重复写记录。
- 列表接口分页，避免一次返回全校学生数据。

### 7.4 可测试性

- 新增权限、观察视角、共享设置、问答、多轮上下文和个人计划自动化测试。
- 保留现有登录、CSRF、IDOR、导出脱敏、任务版本和 SQLite 基线保护测试。

## 8. 实施优先级与建议阶段

### 第一阶段：身份与数据底座（最高优先级）

- 教师观察视角，不注销、不重新登录。
- 教师课程/班级/学生授权查询。
- 班级和学生数据直接读取。
- 学生数据共享白名单与服务端权限。

### 第二阶段：智能问答

- 新问答会话模型。
- 混合检索、真实模型 Provider、引用校验。
- 多轮追问、澄清、通用知识和降级策略。

### 第三阶段：个性化教学闭环

- 个人计划草案、教师编辑与发布。
- 学生今日计划、完成、逾期和反馈。
- 基于新结果生成下一轮调整建议。

### 第四阶段：体验与验收

- 页面重构、加载和错误状态。
- 权限、安全、性能和 50+ 问答集验收。
- 更新免安装发布包、文档和演示脚本。

## 9. 本轮不包含的内容

- 不把教师切换视角实现为共享学生密码或自动登录学生账号。
- 不允许教师看到非本人教学关系内的学生数据。
- 不允许学生查看其他学生数据。
- 不继续把 CSV/JSON 上传作为教师日常分析的前置条件。
- 不将关键词规则包装成“通用大模型问答”。
- 未确认模型服务、费用和数据处理规则前，不接入真实生产密钥。

## 10. 已确认的决策

建议按下列默认方案确认：

1. **身份切换**：采用“教师观察视角”，教师 Session 保持不变，不进行学生身份冒充。
   - 保留学生账号直接登录的完整学生端及本人写权限。
   - 教师观察视角与学生直接登录端并行存在，使用不同的权限上下文。
2. **外部导入**：从教师主导航移除，保留为管理员高级补录工具。
3. **学生选择**：教师先选课程和班级，再从本人授权学生列表进入个人详情。
4. **共享策略**：课程学习相关数据按当前教学关系自动对任课教师开放，学生无需手动选择；其他学生始终不可见。
5. **智能问答模型**：采用可替换的服务端 Provider；在线调用国内可访问模型，未配置时明确降级为离线课程检索。
6. **个性化计划**：系统按学生当前数据自动生成并生效，教师可以查看和修改，无需发布。
7. **数据范围**：继续使用匿名合成演示数据完成比赛版本，不接入真实学校或真实学生信息。

以上 7 项已于 2026-09-20 确认并进入实现。当前实现包含教师授权学生直读、独立学生详情、自动开放策略、会话问答、自动个性化方案持久化和相应权限测试；CloudBase 版本未更新。
